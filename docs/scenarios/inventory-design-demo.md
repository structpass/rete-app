# 在庫管理システム導入の設計開始データ

これは架空案件のテストデータです。従来の倉庫運用サンプルとは別に、システムを作る前から利用者と開発者が同じ場で作業する状況を再現します。

## 案件の前提

青凪システムが北斗機材へ在庫管理システムを導入します。要件定義は2026年10月30日に合意済み。11月2日時点で、基本設計を11月4日から11月20日、詳細設計を11月24日から12月11日まで進める予定です。

対象は本社倉庫と南物流センターの入荷・出荷・在庫照会・倉庫間移動・棚卸。購買発注と請求は対象外です。残る確認は画面配置、入力文言、現行の見出しや棚番との対応です。新たな業務要件は変更相談に分け、設計中の質問への回答だけで範囲を増やしません。

- 商品マスタ18,420件から重複12組・単位未設定37件・廃止区分不明9件を検出。小野寺が調査し、藤原が業務判断、石川が取りまとめます。照会予定は11月5日、回答期限は11月10日です。

- CSVは全行検証し、不正があればファイル全体を登録しません。エラー例と修正後の再取込が、顧客との確認・社内設計・受入条件・実際の資料で対応します。

## 準備と投入

通常の初期投入や既存の試験用固定データを置き換えません。今回の固有識別子で追加し、再投入では既存行と利用者の追記を保持します。タスクは作成履歴に固定の識別子を持たせ、題名を変更しても重複させません。

リポジトリのルートで確認します。

    node scripts/demo/seed-inventory-project.mjs
    node --test scripts/check-inventory-demo.test.mjs

最初のコマンドは投入計画の表示だけです。実際の投入は、開発・試験環境とローカルPostgreSQLに限定します。対象のDB・ファイルの保存先を確認し、PostgreSQLの標準形式で投入前のバックアップを取ってから実行します。

    node --env-file=packages/backend/.env scripts/demo/seed-inventory-project.mjs --apply --storage-root=packages/backend/storage/files --backup=投入前バックアップの絶対パス

NODE_ENV は development または test が必須です。本番名・外部接続先・管理用DBを拒否します。backup は実在する非空ファイルが必須です。接続情報やバックアップをGitへ追加しないでください。

ファイルは固有の保存先にだけ作り、既存の実体を上書きしません。DBへの追加は一つのトランザクションで行います。衝突を検出したら既存行を流用せず停止します。失敗時にはファイル実体だけが残る場合がありますが、元の保存先とバイト列が同じなら再実行できます。

## 確認と撮影

佐伯でログインすると社内と顧客の両方、石川でログインすると顧客向け2チャネルだけが見えます。紹介用の撮影は佐伯を使用します。カレンダーは2026年11月を表示してください。

アプリの実装や既存の権限設定は変更しません。所属と公開範囲は実際のAPIでも確認し、ファイルのダウンロードと版の参照も確認します。撮影画像にはこの架空案件の会話・予定・資料を表示し、古い倉庫運用のサンプルと混ぜません。

資料の再作成には build-inventory-workbooks.mjs（表計算用ライブラリ）と build-inventory-pdfs.py（ReportLab）を使います。これらは資料作成時だけの道具で、アプリや投入時の依存には追加していません。
