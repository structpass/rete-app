# トラック 7 — 運用（問い合わせ・障害・横断メタ機能）

> 記法は [`../README.md`](../README.md)。範囲: 日常の運用で起きる「うまくいかない」への対応、障害時の振る舞い、横断のメタ機能（モデルタブ等）。
> 対象外: 通常の業務操作（→ 各トラック）、開発側の作業票運用（このトラックの対象外）。

## 0. このトラックの性格

成功パスではなく **「失敗した時に何が起きるか」** を扱う。期待結果が決まっていないものが多く、実測して仕様を決めることが目的になる。
分類は「運用イベント」「未確定」が中心で、観点は「復旧・縮退」「画面表示」。

### S-OPS-01-C1 ロックの自然解除と管理者解除（手動）

| 項目   | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 前提   | 検証用のアカウント 1 件。素通し設定は入れない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 手順   | 1. 誤パスワードで 6 回失敗<br>2. 正しいパスワードで 1 回<br>3. 15 分待って再度 1 回<br>4. 管理者が解除して 1 回<br>5. 同じアカウントをもう一度 6 回失敗させ、管理者が `/settings/members` の行編集でロック中バッジと「今すぐロックを解除」を押す                                                                                                                                                                                                                                                                                                                  |
| 期待   | 1. 5 回目までは 401「メールアドレスまたはパスワードが正しくありません」。6 回目から 429 で「アカウントがロックされています（自動解除まで約15分）。お急ぎの場合は管理者に解除を依頼してください」。<br>2. 429（ロック中は資格情報を検証しない）。<br>3. 通る（期限超過で失敗回数がリセットされる）。<br>4. 通る（`PATCH /members/{id}/unlock`・ADMIN 限定。MEMBER は 403）。<br>5. 解除すると自動解除まで待たずに入れる                                                                                                                                            |
| 後始末 | 手順 4・5 で解除                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 実行   | 手順 1・2・4・5 は自動 `@S-OPS-01`（`ops-resilience.feature`）。自動が確かめるのは、6 回試した後の 429・ロック中に正しいパスワードでも 429 になること・文言の目安・解除後の 200。**「5 回目までは 401」は自動では主張しない**（自動は 6 回目以降をまとめて 429 で見る。5 回目が 401 であることは実測の記録に残し、閾値そのものは `account.repository.ts` の `+1 後 >= maxAttempts` が固定する）。手順 3 だけ手動。理由: 待ち時間が 15 分あり、自動実行に載せると遅く不安定になる（期限超過で解除されることは `auth.service.spec` のロックアウト節で固定している） |

## 3. このトラックの未確定事項

| 論点                                               | 影響                             | 決める場所 |
| -------------------------------------------------- | -------------------------------- | ---------- |
| 障害・メンテナンスの周知経路（自動配信を持たない） | 現場への到達が運任せ             | 決定       |
| 製品内の不具合報告導線                             | 報告が口頭に流れ、記録が残らない | 決定       |
| 権限不足を不具合と誤解させない説明                 | 問い合わせ増                     | 決定       |

- ロック解除の経路（自動／管理者）と案内文言は、2026-10-28 の実測で決まった（5 回目の失敗でロックが立ち、その応答は 401。ロック中は資格情報を検証しないため 6 回目から 429・自動解除まで約 15 分。管理者は `PATCH /members/{id}/unlock` で即時解除・MEMBER は 403）。S-OPS-01 を ✅ にした。
- 社外ゲストへの通知到達は、社外ゲストの受け入れ自体が未実装（`operational-policy` §7.1）のため、確かめる対象が無い。S-OPS-09 を対象外にした。
